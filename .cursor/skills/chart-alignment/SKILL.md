# 图表对齐判断

核对画面和用户的三句话是否对齐。成品是一份判断。

下结论前先读 [examples.md](examples.md)。用那里的尺度，不要把例句的结论套到新图上。

## 输入

三件事可以挤在一段话里。先拆成三句：

1. 要回答什么
2. 给谁看
3. 看完该做什么

同时需要一张已经画好的图。标题、图、解读文案、按钮属于同一张画面，一起判断。

某一槽是空的，或根本没有图：停下，只问缺的那一项。不要开始判断，不要替用户补全。

## 先审三句话

一句要具体到能被这张图证伪，该轴才打分。说不清的那一轴暂停，其余轴继续。

- **要回答什么**：说得清在表达哪一项指标、哪一段范围。只说「看看表现如何」不可核对。
- **给谁看**：要能判断熟悉度（这个人能否读懂这种图）和责任（这个数字在他身上的重量）。只写「用户」「高管」不可核对。
- **看完该做什么**：要有一个能在画面上寻找的动作，包括「暂时不用改」。只说「了解一下」不可核对。

暂停时写明这句为什么还不能核对。不要把职位或「用户」升级成一种读者。

## 再审图

只给可核对的轴打分。每轴只取一个结论：对齐、部分对齐、未对齐。证据必须是画面上看得见的文字、颜色、位置、有没有按钮。不推测图里没写的数据。

**背景。** 比较、范围、留下的和拿掉的，是否在回答那句话。主图已经回答、相邻模块改口讲另一件事，记部分对齐。汇总数字一致，但形状、离群点或比例会改写判断的，以图形为准，记未对齐。没有坐标轴本身不是失败，除非那个问题离开刻度就答不上。

**受众。** 熟悉度不够、图的读法超出这个人的直觉，记未对齐。责任决定密度：要往下查原因的人需要能诊断的密度；要调资源的人需要先看见结论的密度。密度和这个重量不相称，记未对齐。同一张图同时塞给这两种人，记未对齐。

**洞察。** 看完该做的那一步要能在画面上找到，而且先于细节被看见。会改写这一步的变量要出现在同一视野里。只发出警报、没带上会改写动作的变量，记未对齐。下一步有两步时，画面上缺更重的那一步，记未对齐。通往这一步的文案把话题带到别的对象上，记未对齐。

数据墨水比只用来识别装饰。不服务数据的装饰可以指出。简洁本身不是通过条件。拿掉决策需要的上下文，记未对齐。已经服务于三句话的编码，不要建议删掉。

## 输出

用用户使用的语言，按这个顺序写：

1. 三句话是否可核对。点明哪一句暂停。
2. 背景、受众、洞察。每轴先写结论，再写画面证据。暂停的轴不打分。
3. 要对齐，画面上改的那一处。写清改哪一块、改成什么。多轴未对齐时，只选能解开最重那一轴的一处，不列清单。可核对的轴都是对齐：写对齐，不追加修改。

## 不做的事

- 不重画，不换图表类型，不从已有指标建议加图。
- 不把「再干净一点」当作修改意见。
- 不在判断里补设计方案之外的第二处、第三处。
